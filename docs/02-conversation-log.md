# 02 · 对话记录（结构化）

> 记录双方三轮问答的要点与结论。第一人称“我”= AI 助手。

---

## R1 · 能否准确识别电路图？

**用户**
> 你能否准确识别电路图。如果不可以，我把电路图给你，你能转换成你能精确理解的图或者结构吗

**我的回答（要点）**

1. **能看，但不能保证准确。** 可读取图片/PDF 页/截图并描述拓扑大意；但工程级准确不可保证。具体风险：
   - 引脚编号与字母（`U3-A`、`B12`）
   - 网络标号（`KL30`、`CAN_H`、`VCC_5V`）
   - 交叉但不相连、总线（bus）与分线、跨页连接符
   - 阻容值与器件型号（`100nF` vs `10nF`）
   - 一旦错进网表，后续电气分析/测试用例/验证结论全部失效

2. **不要我去“认”图，要转成我能精确处理的“声明式结构”。** 三条路径按可靠性递减：
   - **A 源文件/网表**：KiCad `.kicad_sch`、Altium `.SchDoc`、Cadence `.dsn`、Eagle `.brd`、通用 `.net/.xml/.asc/.tel` + BOM + PDF → 零识别误差
   - **B 矢量 PDF**：抽文字层得到 refdes/网络名/值的**坐标**；抽线段矢量按端点聚类重建连接；可自动生成网表 + 重绘 SVG 供双向核对
   - **C 位图（截图/照片/扫描）**：只能出**带置信度的草稿**，必须人工复核；用于“看懂、找疑点”，不能单独作为验证依据

3. **推荐的目标结构**（我能精确推理的三元关系：元件—引脚—网络）：

```json
{
  "components": [
    {"ref": "U3", "part": "BSS138", "pins": {"1":"G","2":"S","3":"D"}},
    {"ref": "R12", "part": "10k", "pins": {"1":"a","2":"b"}}
  ],
  "nets": [
    {"name": "VCC_5V", "nodes": ["U3.1", "R12.1", "J2.4"]},
    {"name": "N_0142",  "nodes": ["R12.2", "U3.3"]}
  ]
}
```
同样接受 KiCad 网表、SPICE（`.cir`）、Graphviz DOT / Mermaid。

4. **可交付流水线**：`inputs/` 放文件 → 产出 `netlist.json`（精确结构）、`schematic.svg`（重绘供核对）、`report.md`（不确定项/低置信点清单 + 拓扑检查结果）。

**追问确认**：图纸形式 = 位图；用途 = 看懂拓扑 + 找可疑点（→ 走 C 路线）。

## R2 · 能否做成网页，让我核对/编辑/保存？

**用户**
> 你能否根据图片转换成 html 网页，然后我核对，如果不正确，我能编辑电路图，并保存。你需要在网页中提供修改电路图的基本功能的模块。以上方案是否可行，你是否有更好的方案。

**我的回答（要点）**

**可行，但原方案有三个隐含问题：**

1. **“重绘原理图” vs “原图对比”**：网页里的是重绘件，几何必然与原图不同，人眼对图容易产生“照着画改”而不是“照事实改”的偏差 → 需要**原图并排 + 表格化核对**。
2. **纯视觉编辑无法表达网表事实**：导线交叉 vs 连接在画面上几乎一样，而这正是识别最易错处 → 需要显式的 junction 语义与“不连接”标记。
3. **保存必须是结构化数据**：存 PNG 对下游毫无价值 → 必须存 JSON 网表，且能回灌给我做分析。

**更好的方案（已实现）**：以“网表为源、图为视图”的联动工作台

- 左：原图参考（可缩放，可把元件“钉”到图上）
- 中：可编辑 SVG 画布
- 右：**网络表**（核对主界面）/ 元件表 / 属性 / ERC
- 双向联动：点表格定位画布；画布改动即时重算网表
- **置信度与复核状态**：位图识别结果标为 draft，逐项确认后升级为事实
- 导出：工程 JSON（可还原）/ 网表 JSON（机器可读）/ Markdown（人工）/ SVG / PNG
- **单文件、离线、无依赖**

**同时说明边界**：编辑器不修复糟糕的识别，它只让**纠错变便宜且可审计**；图很大时要按页/按功能块拆分。

## R3 · 有没有开源方案？

**用户**
> 思考目前是否有开源的解决这种问题的方案

**我的回答（要点）**

把问题拆成三层，开源成熟度差异极大：

| 层 | 开源现状 | 能否直接用 |
|---|---|---|
| ① 位图 → 结构（识别） | 只有学术原型，需 GPU + 训练数据 | ❌ |
| ② 结构 → 可编辑 + 可保存 | 很成熟，多个可选 | ✅ |
| ③ 结构 → 电气分析（网表/ERC） | 成熟 | ✅ |

**结论：唯一没有现成开源方案的是第①层。** 真实结论是——用成熟开源接管②③层，把①层降级为“算法/AI 出草稿 + 人工复核”。

代表项目：
- 识别：SPICEnet（CNN 元件检测）、CircuitVision（YOLOv11 + SAM 2.1 + Gemini → SPICE）、SINA（论文级 image→netlist）
- 编辑/格式：KiCad + `kicad-cli`（文本 `.kicad_sch`，**推荐作为交换格式**）、KiCanvas（浏览器渲染 KiCad）、QElectroTech（电气图编辑器，XML）、tscircuit（声明式电路 + 原理图渲染）、netlistsvg（网表→SVG）、draw.io/maxgraph（通用图编辑内核，无电路语义）、Fritzing（面包板→原理图，netlist 模型可借鉴）
- 分析：circuitgraph（SPICE 网表成图，做电气一致性检查）、KiCad ERC、kiutils / kicad-skip（解析 `.kicad_sch`）、SKiDL

**建议三套组合**
- **A（最省力）**：拿到源文件 → `altium2kicad` 等转换 → 网表 + ERC；或拿到矢量 PDF → `pdfplumber`/`PyMuPDF` 抽文字层与线段，**比像素 OCR 高一个数量级**
- **B（推荐）**：开源做后端，自研“复核层”——AI 出带置信度草稿 → 人逐条确认 → 导出结构化网表喂给 KiCad / circuitgraph
- **C（零研发）**：人工在 KiCad 重画 → `kicad-cli` 出网表 → ERC；量大不划算

**并说明**：已经顺便把 B 的复核层做成了可运行原型（即本仓库 `app/`）。
